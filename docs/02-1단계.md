# 1단계 — 로그인 + 계정과목 불러오기 + 전표 저장(차대 검증)

## 만든 것

| 영역 | 내용 |
|---|---|
| 로그인 | 이메일+비밀번호 로그인·회원가입(확인 메일), 비밀번호 찾기(메일 링크 → 새 비밀번호), **로그인 유지** |
| 앱 뼈대 | 하단 고정 탭 바(대시보드/입력/거래목록/보고서/설정), 떠 있는 **[+ 입력]**, 상단 장부 이름·온라인 표시, 다크 모드(자동/라이트/다크) |
| 계정과목 | 장부의 계정 불러오기 → 분류별 2단계 트리로 표시 (설정 → 계정과목) |
| 고급 입력 | 여러 줄 분개, 금액 입력 시 숫자 키패드·천 단위 쉼표 자동, **실시간 차변·대변 합계와 차액**, 차대가 맞을 때만 [저장] 활성, "이렇게 기록됩니다" 미리보기 |
| 저장 | DB 함수 `create_transaction` 호출 → DB가 차대를 **다시** 검사. 실패해도 입력 내용 유지, 같은 전표 id로 재시도(중복 저장 방지) |
| 대시보드 | 장부 상태(순자산·자산·부채·누적 손익) + **장부 검증**(차대 합계, 불균형 전표, 회계 등식) |
| 최근 전표 | 입력 화면 아래 최근 10건 (차변/대변 줄 표시) |
| 점검 도구 | `check.html`(Supabase 연결 확인), `tests.html`(회계 로직 자동 테스트 17건) |

### 파일 구조 (회계 로직과 화면 분리)
```
js/core/      회계 로직 — 화면 코드 없음 (money.js, balance.js, journal.js, tests.js)
js/data/      Supabase 연결·API·한국어 오류 메시지
js/ui/        화면 (auth.js, shell.js, screens/*.js, 공통 도우미)

```

### 아직 없는 것 (다음 단계)

- 거래 목록(검색·필터)·전표 수정·삭제·휴지통, 원장·시산표 → **3단계**
- 가족 초대 화면 → 2단계 이후 설정 화면에 추가 (DB 기능은 이미 있음)

## 확인 방법

### 0. 자동 테스트
- `tests.html`을 열어 **✅ 17건 모두 통과**를 확인합니다 (설정 → 점검 도구 → 회계 로직 자동 테스트).

### 1. 로그인
1. 앱 주소를 열면 로그인 화면이 나옵니다. **회원가입** 탭에서 이메일·비밀번호(6자 이상)를 입력합니다.
2. "확인 메일을 보냈습니다"가 나오면 메일의 링크를 누릅니다 → 앱으로 돌아와 자동 로그인됩니다.
3. 앱을 닫았다가 다시 열면 **로그인이 유지**됩니다.
4. (선택) 로그아웃 → **비밀번호를 잊으셨나요?** → 메일 링크 → 새 비밀번호 설정 화면이 나오는지 확인합니다.

### 2. 계정과목
- 설정 → 계정과목: **27개**, 분류 5개(자산·부채·순자산·수익·비용), "보통예금 > 주거래 통장", "신용카드 > 주 사용 카드" 2단계 구조가 보이면 정상입니다.

## 1단계 테스트 시나리오 (복식부기)

모두 **입력 → 고급 입력**에서 합니다. 각 단계 뒤 **대시보드**에서 숫자를 확인하세요.

| # | 입력 (차변 / 대변) | 화면에서 확인 | 대시보드에서 확인 |
|---|---|---|---|
| 1 | **개시 잔액** (메모 "개시 잔액")<br>차변 현금 100,000<br>차변 보통예금 > 주거래 통장 2,000,000<br>대변 신용카드 > 주 사용 카드 300,000<br>대변 기초 순자산 1,800,000 | 차변 합계 2,100,000 = 대변 합계 2,100,000, 차액 0, [저장] 활성 | 순자산 **1,800,000**, 자산 2,100,000, 부채 300,000, 검증 3개 모두 ✔ |
| 2 | **차대 불일치 시도**<br>차변 식비 30,000 / 대변 현금 29,000 | 차액 **1,000** 빨간색, "대변이 부족" 안내, [저장] **비활성** | (저장 안 됨) |
| 3 | **카드로 식비 3만 원**<br>차변 식비 30,000 / 대변 신용카드 > 주 사용 카드 30,000 | 미리보기 "차변 식비 30,000 / 대변 신용카드 > 주 사용 카드 30,000" | 순자산 **1,770,000** (3만 원 감소), 누적 손익 **-30,000** |
| 4 | **카드대금 결제**<br>차변 신용카드 > 주 사용 카드 330,000 / 대변 보통예금 > 주거래 통장 330,000 | 저장 성공 | 순자산 **그대로 1,770,000**, 부채 **0**, 자산 1,770,000, 검증 ✔ |
| 5 | **급여 (여러 줄)**<br>차변 주거래 통장 3,000,000<br>차변 세금·사회보험 300,000<br>대변 급여 3,300,000 | [+ 줄 추가]로 3줄 입력, 합계 일치 | 순자산 **4,770,000** |
| 6 | **소수·한쪽 입력 확인**<br>금액란에 `1000.5` 입력 시도, 같은 줄 차변·대변 동시 입력 시도 | 점(.)이나 문자를 누르면 입력되지 않고 "원 단위 정수만 입력할 수 있습니다" 안내가 뜸. 같은 줄에서 차변을 입력하면 대변이, 대변을 입력하면 차변이 자동으로 비워짐 | — |

> 테스트용 전표는 3단계에서 휴지통 기능이 생기면 지울 수 있습니다. 실제 사용 전에 깨끗한 장부가 필요하면 말씀해 주세요. 정리용 SQL을 드리겠습니다.

### DB 이중 장치 확인 (화면 검증을 건너뛰고 DB에 직접 불균형 전표 보내기)
로그인한 상태로 PC 브라우저에서 **F12 → Console**에 붙여넣고 Enter:
```js
const { supabase, state } = ledgerDebug;
const acc = (name) => state.accounts.find((a) => a.name === name).id;
const { error } = await supabase.rpc('create_transaction', {
  p_id: crypto.randomUUID(), p_ledger_id: state.ledgerId, p_date: '2026-01-01',
  p_memo: '불균형 테스트', p_kind: 'manual', p_source: 'advanced',
  p_lines: [{ account_id: acc('식비'), debit: 30000 }, { account_id: acc('현금'), credit: 29000 }],
});
console.log(error?.message);
```
→ `차변 합계(30000)와 대변 합계(29000)가 일치하지 않습니다. 차액 1000원` 이 나오면 정상입니다. (저장되지 않음)

```js
// 전표 테이블에 직접 쓰기 시도 → 막혀야 함
const r = await ledgerDebug.supabase.from('transactions').insert({ id: crypto.randomUUID(), ledger_id: ledgerDebug.state.ledgerId, txn_date: '2026-01-01' });
console.log(r.error?.message);   // permission denied ... 이 나오면 정상
```

## RLS(보안) 확인 — 다른 계정으로 접근 시도

1. **계정 A**(위 시나리오를 입력한 계정)로 로그인 → 설정 → 장부 ID **복사**.
2. 다른 브라우저 또는 시크릿 창에서 **계정 B**로 가입·로그인합니다.
   (Gmail이라면 `내주소+b@gmail.com`처럼 `+`를 붙이면 같은 메일함으로 받습니다)
3. B의 대시보드: 순자산 0, 최근 전표 없음 → B에게는 A의 데이터가 보이지 않습니다.
4. B 브라우저에서 F12 → Console에 붙여넣고, 첫 줄의 따옴표 안에 A의 장부 ID를 넣은 뒤 Enter:
```js
const A_LEDGER = '여기에 A의 장부 ID';
const sb = ledgerDebug.supabase;
const count = async (t) => (await sb.from(t).select('*').eq('ledger_id', A_LEDGER)).data?.length;
console.table({
  계정과목: await count('accounts'),
  전표: await count('transactions'),
  분개: await count('lines'),
  이력: await count('audit_log'),
});
const bal = await sb.rpc('account_balances', { p_ledger_id: A_LEDGER });
console.log('잔액 조회 행 수:', bal.data?.length);
const ins = await sb.rpc('create_transaction', {
  p_id: crypto.randomUUID(), p_ledger_id: A_LEDGER, p_date: '2026-01-01', p_memo: '침입', p_kind: 'manual',
  p_source: 'advanced', p_lines: [{ account_id: crypto.randomUUID(), debit: 1 }, { account_id: crypto.randomUUID(), credit: 1 }],
});
console.log('A 장부에 저장 시도:', ins.error?.message);
```
**정상 결과**: 표의 숫자가 모두 **0**, 잔액 조회 행 수 **0**, 저장 시도는 `이 장부에 접근할 권한이 없습니다.`
