# 추가 기능 — 거래 시각(시:분) 입력과 시간순 정렬

## ⚠️ 먼저: DB 업데이트 (한 번만)

1. Supabase **SQL Editor** → **New query**
2. [`sql/migrations/005_txn_time.sql`](../sql/migrations/005_txn_time.sql) 전체를 붙여넣고 **Run** → **Success**
3. (권장) [`sql/tests.sql`](../sql/tests.sql) 다시 실행 → **✅ 모든 테스트 통과** (시각 저장·정렬·수정·원장·복원 점검 추가)

> 실행하지 않으면 앱을 열 때 "DB 업데이트가 필요합니다 (현재 4 → 필요 5)" 안내가 뜨고 저장이 되지 않습니다.
> **주의:** 005를 실행한 뒤에는 예전 업데이트(002~004)를 **다시 실행하지 마세요.** 002를 다시 실행하면 거래 검색 함수가 옛 모양으로 하나 더 생겨 거래 목록이 열리지 않을 수 있습니다. (실수로 실행했다면 005를 한 번 더 실행하면 옛 함수가 지워져 원래대로 돌아옵니다)

## 정한 규칙

| 항목 | 규칙 |
|---|---|
| 새 입력 | 날짜 옆 **시각 칸에 지금 시각**이 자동으로 들어 있음 → 보통은 그대로 저장(지출 3터치 유지). 지난 거래는 시각만 고치면 됨. 칸을 비우면 "시각 없음" |
| 저장 | 시:분까지 (초는 버림). 날짜와 따로 저장하므로 재무상태표·손익계산서·예산·월별 그래프는 바뀌지 않음 |
| 시각 없는 전표 | 기존 전표, 개시 잔액, 반복 거래 등 → 같은 날의 **맨 앞(00:00 취급)**, 표시는 시각 없이 |
| 거래 목록 | 필터 아래 **[최신순 ↓] / [오래된순 ↑]** — 날짜 → 시각 → 입력한 순서. 마지막 선택을 기기에 기억 |
| 함께 바뀐 곳 | 전표 상세(시각 표시), 수정(시각 바꾸기·지우기), 변경 이력("시각 21:30 → 20:00"), 계정별 원장(같은 날은 시각 순, 누적 잔액도 그 순서), 분개장·원장 CSV(시각 열), 백업·복원(시각 포함) |
| 은행·카드 내역 가져오기 | 날짜 칸에 붙은 시각(2026.11.01 09:12) 또는 따로 있는 시각 열(승인시간 등)을 자동으로 읽어 함께 저장. 오전/오후 표기, 엑셀 시각 칸도 처리 |

- 시간 기능 이전 앱(휴대폰에 남아 있는 옛 화면)으로 저장해도 문제없습니다. 시각만 비어 있게 됩니다. 옛 화면으로 전표를 고치면 시각은 그대로 유지됩니다.
- 자동 테스트: `tests.html` **67건** (지금 시각·입력 확인·표시, 시간순 비교, 파일의 시각 읽기 추가)

## 테스트 시나리오

1. 입력 → 간편 입력: 날짜 옆 **시각 칸에 지금 시각**이 들어 있는지 확인.
2. 같은 날짜로 지출 3건 저장:
   - "저녁" 25,000 · 시각 **21:30**
   - "아침" 4,500 · 시각 **08:05**
   - "시각 없음" 1,000 · 시각 칸을 **비움**
3. 거래 목록(이번 달):
   - **최신순 ↓**: 그날 안에서 저녁(21:30) → 아침(08:05) → 시각 없음 순서, 시각이 함께 보임
   - **오래된순 ↑**: 시각 없음 → 아침 → 저녁
   - 앱을 닫았다 열어도 마지막 정렬이 유지됨
4. "저녁" 상세 → 시각 21:30 → [수정] → 시각 칸에 21:30이 들어 있음 → **20:00**으로 바꿔 저장 → 상세의 변경 이력에 "시각 21:30 → 20:00".
5. 보고서 → 계정별 원장(식비, 이번 달): 그날 줄이 아침 → 저녁 순서, 누적 잔액도 그 순서로 늘어남.
6. (선택) 시각이 들어 있는 은행·카드 파일을 가져오기 → 미리보기에 시각이 보이고, 가져온 뒤 거래 목록에서 그 시각 순서로 정렬됨.
7. 시산표·대시보드 숫자는 시각 입력 전과 같은지(시각은 금액에 영향 없음) 확인.
