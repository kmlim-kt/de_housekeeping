## 1. 화면 구성

하단 고정 탭 바: **대시보드 / 입력 / 거래목록 / 보고서 / 설정**, 그리고 떠 있는 **[+ 입력]** 버튼

| 화면 | 주요 구성 |
|---|---|
| 로그인 | 이메일(매직링크 또는 비밀번호), 구글 로그인 |
| 개시 잔액 마법사 | 첫 로그인 시 계좌·카드·대출 잔액 입력 → 기초 순자산 자동 계산 → 개시 전표 1건 생성 |
| 대시보드 | 이번 달 수입·지출·저축률, 순자산 추이 그래프, 예산 대비 지출, 저장 대기 건수 |
| 입력 | [간편] 지출(기본)·수입·이체·카드대금·대출상환 / [고급] 여러 줄 분개, 하단에 "이렇게 기록됩니다" 미리보기 |
| 거래목록 | 분개장, 날짜·계정·메모·금액 필터와 검색, 휴지통 |
| 보고서 | 계정별 원장, 시산표, 재무상태표, 손익계산서, 예산, 장부 검증 (휴대폰에서는 카드형) |
| 설정 | 계정과목 관리, 반복 거래, 즐겨찾기, 백업·내보내기·가져오기, 다크 모드, 로그아웃 |

**지출 3터치 흐름**: ① [+ 입력] → (금액 칸에 자동 포커스, 숫자 키패드) 금액 입력 → ② 비용 칩 선택(최근 사용순) → ③ [저장]
결제수단은 최근에 쓴 계정을 기본값으로, 날짜는 오늘을 기본값으로 둡니다.

## 2. 파일 구조 (빌드 도구 없이 ES 모듈 사용)

```
index.html          진입점 (단일 페이지)
config.js           Supabase URL·anon key (이 파일 한 곳에서만 관리)
manifest.json, sw.js, icons/   PWA
css/app.css         라이트·다크 테마
js/core/            ★ 회계 로직 — DOM 코드 없음, 화면과 분리
   money.js         금액 파싱·천 단위 쉼표 (정수만 사용)
   journal.js       간편 입력 → 분개 변환, 차대 검증·차액 계산
   balance.js       잔액 부호 규칙 (자산·비용=차변+, 부채·순자산·수익=대변+)
js/data/            Supabase 클라이언트, RPC·조회, 오프라인 대기열(IndexedDB)
js/ui/              화면별 렌더링·이벤트 (core를 호출만 함)
sql/schema.sql      테이블·제약·함수·뷰·트리거·RLS 전체
tests.html          core 로직 브라우저 테스트 (제안)
```

## 3. 데이터 흐름

**저장**
```
입력 화면 ─▶ core/journal.js : 분개 라인 생성 + 차대 검증 (불일치면 저장 버튼 비활성, 차액 표시)
         ─▶ 대기열(IndexedDB)에 저장 (전표 id는 기기에서 UUID로 미리 생성)
         ─▶ 온라인이면 즉시 RPC save_transaction 호출 / 오프라인이면 대기, 연결되면 자동 전송
         ─▶ DB: auth.uid() 확인 → 계정 소유 확인 → 차변 합계 = 대변 합계 확인 → 저장 (실패 시 전체 롤백)
         ─▶ 트리거가 audit_log 기록 → 성공 시 대기열에서 제거 → 화면 갱신
```

**조회**
```
화면 ─▶ js/data (뷰·함수 호출, RLS 적용) ─▶ core (부호·합계 계산 검증, 포맷) ─▶ 렌더링
```

## 4. DB 설계 개선 제안 (원안 대비)

1. **멱등 저장**: 전표 id를 기기에서 만들어 RPC에 넘깁니다. 오프라인 재전송이 여러 번 일어나도 같은 전표가 중복 저장되지 않습니다.
2. **쓰기 경로 일원화**: `transactions`·`lines`에는 RLS로 **조회만** 허용하고, 쓰기는 RPC로만 받습니다. 추가로 커밋 시점에 차대를 다시 검사하는 지연 제약 트리거(deferred constraint trigger)를 둡니다.
   → 화면 검증, RPC 검증, 커밋 검증의 **3중 장치**가 됩니다.
3. **`transactions`에 열 추가**
   - `kind`: expense·income·transfer·card_payment·loan_repayment·opening·manual
   - `source`: simple·advanced·recurring·import
   → 간편 입력으로 저장한 전표를 다시 간편 입력 화면으로 수정할 수 있습니다.
4. **`accounts`에 열 추가**
   - `is_system`: 기초 순자산처럼 지울 수 없는 계정
   - `subtype`: cash·bank·card·loan 등으로 간편 입력의 선택지를 거르는 데 씁니다.

   계층은 2단계까지로 제한합니다(트리거). **하위 계정이 있는 상위 계정에는 직접 분개할 수 없게** 합니다. 거래가 있는 계정은 삭제 대신 숨김만 허용합니다.
5. **`recurring` 구조화**: 자유 텍스트 `rule` 대신 `freq`(매월·매주·매년), `day`, `start_date`, `end_date`, `next_date`, `template`(jsonb)을 둡니다.
6. **`favorites` 테이블 추가**: 원안에 없던 즐겨찾기용입니다.
7. **뷰는 `security_invoker = true`**: 뷰에도 RLS가 적용됩니다. 휴지통에 있는 전표(`is_deleted`)는 모든 집계에서 제외합니다.
8. **`audit_log`는 트리거로 자동 기록**: 사용자는 조회만 할 수 있습니다.
9. 열 이름 `date`는 SQL 예약어라서 `txn_date`로 바꿉니다.
10. `lines`에 `user_id`를 함께 저장합니다. RLS와 인덱스를 단순하게 만들기 위해서이고, RPC가 일관성을 보장합니다.

## 5. 기본값으로 정한 사항 (이의 있으면 말씀해 주세요)

- **오프라인 지원 범위**: 오프라인에서는 **신규 입력만** 대기열에 저장합니다. 수정·삭제는 온라인에서만 가능하게 해 충돌을 막습니다.
- **카드 할부**: 구매 시 전액을 카드 부채로 잡고, 결제할 때마다 카드대금 결제로 나눠 갚습니다. 할부 전용 기능은 만들지 않습니다.
- **저축률**: (수입 − 지출) ÷ 수입
- **예산**: 비용 계정별로 설정합니다. 상위 계정에 예산을 두면 하위 계정 지출을 합산합니다.
- **보고서 기준일**: 재무상태표는 선택한 날짜까지의 누계로 계산합니다. 손익계산서는 선택한 월 또는 연도로 계산합니다.

## 6. 결정 사항 (2026-11-06)

| 항목 | 결정 |
|---|---|
| 장부 공유 | **가족 공유 장부**: 장부(ledger) 단위로 데이터를 묶고, 다른 계정을 초대해 함께 씁니다 |
| 반복 거래 | **앱을 열 때 확인 후 등록**: 날짜가 된 건을 '등록 대기' 목록으로 보여 주고, 확인하거나 수정한 뒤 저장합니다 |
| 그래프 | **Chart.js** (CDN, 버전 고정) |
| 로그인 | **이메일+비밀번호**로 시작합니다. 구글 로그인은 0단계 안내에 선택 항목으로 넣고 나중에 켭니다 |

### 공유 장부 반영에 따른 구조 변경

- **새 테이블**
  - `ledgers`(id, name, created_by)
  - `ledger_members`(ledger_id, user_id, role: owner·member)
  - `ledger_invites`(ledger_id, email, role, token, expires_at)
- 모든 데이터 테이블(accounts, transactions, lines, budgets, recurring, favorites, audit_log)의 소유 기준을 `user_id`에서 **`ledger_id`**로 바꿉니다. `created_by`(작성자 user_id)는 따로 기록합니다.
- **RLS**: "내가 `ledger_members`에 속한 장부의 데이터만" 읽고 쓸 수 있습니다. 판별 함수는 `is_ledger_member(ledger_id)`를 씁니다.
- **RPC**: auth.uid()가 해당 장부의 구성원인지 매번 검사합니다.
- **신규 가입 트리거**: 개인 장부 1개, owner 멤버십, 기본 계정과목을 자동으로 만듭니다.
- **초대 흐름**: owner가 이메일로 초대 코드를 만들어 전달합니다. 초대받은 사람이 가입하거나 로그인한 뒤 코드를 입력하면 장부에 합류합니다. 메일 발송 서버가 필요 없는 방식입니다.

### 추가로 정한 기본값 (이의 있으면 말씀해 주세요)

- **권한**: owner와 member 모두 전표 입력·수정·삭제가 가능합니다. 구성원 초대·내보내기와 장부 삭제는 owner만 할 수 있습니다.
- **장부 개수**: 한 사람이 여러 장부에 속할 수 있고, 화면 상단에서 장부를 전환합니다. 기본 장부는 1개입니다.
- **작성자 표시**: 전표마다 누가 입력했는지 거래 목록에 표시하고, 이력(audit_log)에도 남깁니다.
