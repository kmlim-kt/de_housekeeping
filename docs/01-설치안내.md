# 0단계 — 설치 안내 (Supabase → schema.sql → config.js → GitHub Pages)

처음 하는 분도 따라 할 수 있게 순서대로 적었습니다. 전체 20~30분 정도 걸립니다.
각 단계 끝의 **✅ 확인**이 되면 다음으로 넘어가세요.

---

## 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에 접속 → **Start your project** → GitHub 계정으로 로그인합니다.
2. **New project**를 누르고 아래처럼 입력합니다.
   | 항목 | 입력 값 |
   |---|---|
   | Name | `de-housekeeping` (아무 이름이나 괜찮습니다) |
   | Database Password | **Generate a password**를 누른 뒤 **꼭 따로 저장** |
   | Region | **Northeast Asia (Seoul)** |
   | Plan | Free |
3. **Create new project**를 누르고, 1~2분 정도 준비가 끝나기를 기다립니다.

> 💡 무료 플랜은 **일주일 동안 접속이 없으면 프로젝트가 일시 정지**됩니다. 이 경우 대시보드에서 **Restore**를 누르면 데이터 그대로 다시 켜집니다.

✅ 확인: 프로젝트 대시보드 화면이 보이면 됩니다.

---

## 2. schema.sql 실행 (DB 만들기)

1. 왼쪽 메뉴에서 **SQL Editor**를 열고 **New query**를 누릅니다.
2. 이 저장소의 [`sql/schema.sql`](../sql/schema.sql) 파일 내용을 **전부** 복사해 붙여넣습니다.
3. 오른쪽 아래 **Run**(또는 Ctrl+Enter)을 누릅니다.
   - "Potential issue detected"(위험할 수 있는 쿼리) 경고가 뜨면 **Run this query**를 누르세요. 권한을 정리하는 `revoke` 문 때문에 뜨는 경고입니다.
4. **Success. No rows returned**가 나오면 성공입니다.

> ⚠️ schema.sql은 **한 번만** 실행합니다. 다시 실행하면 "already exists" 오류가 납니다. 잘못되어 처음부터 다시 하고 싶으면 말씀해 주세요. 초기화용 SQL을 드리겠습니다.

✅ 확인: 왼쪽 **Table Editor**에 `accounts`, `transactions`, `lines` 등 10개 테이블이 보입니다.

---

## 3. tests.sql 실행 (회계 로직·보안 자동 점검)

1. SQL Editor에서 **New query**를 하나 더 열고, [`sql/tests.sql`](../sql/tests.sql) 내용을 전부 붙여넣고 **Run**을 누릅니다.
2. 결과에 **`✅ 모든 테스트 통과 (테스트 데이터는 삭제되었습니다)`**가 나오면 성공입니다.
   - 테스트용 가짜 사용자 2명을 만들어 점검한 뒤 모두 지웁니다. 실제 데이터에는 영향이 없습니다.
   - 실패하면 `❌ [테스트 이름]`이 담긴 오류 메시지를 그대로 복사해 알려 주세요.

이 테스트가 확인하는 내용(0단계 테스트 시나리오)은 아래 [7장](#7-0단계-테스트-시나리오)에 정리했습니다.

✅ 확인: `✅ 모든 테스트 통과`

---

## 4. 로그인(Auth) 설정

1. 왼쪽 **Authentication** → **Sign In / Providers**(또는 Providers)에서 **Email**이 켜져 있는지 확인합니다.
   - **Confirm email**은 켜 둔 상태를 권장합니다. 가입하면 확인 메일이 옵니다.
2. **Authentication → URL Configuration**에서 아래와 같이 입력합니다.
   - **Site URL**: `https://kmlim-kt.github.io/de_housekeeping/`
   - **Redirect URLs**에 추가:
     - `https://kmlim-kt.github.io/de_housekeeping/**`
     - `http://localhost:5500/**` (내 PC에서 개발·테스트할 때 사용)
3. **Save**를 누릅니다.

> 💡 Supabase 기본 메일 발송은 **시간당 몇 통 정도로 제한**됩니다. 가족이 가입하는 정도에는 충분합니다. 부족하면 나중에 SMTP(예: Gmail)를 연결하면 됩니다.

✅ 확인: Site URL이 저장되어 있습니다.

---

## 5. config.js 설정

1. **Project Settings**(톱니바퀴) → **API Keys**(화면에 따라 **API**)로 갑니다.
2. 아래 두 값을 복사합니다.
   - **Project URL**: `https://xxxxxxxx.supabase.co` 형태입니다. Data API 메뉴나 프로젝트 첫 화면의 **Connect** 버튼에도 있습니다.
   - **공개 키**: **Publishable key**(`sb_publishable_...`) 또는 **Legacy API Keys** 탭의 **anon public** 키
3. 저장소의 [`config.js`](../config.js)를 열어 예시 값을 바꿉니다.
   ```js
   export const SUPABASE_URL = 'https://xxxxxxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'sb_publishable_...';
   ```

> ⛔ **service_role 키, secret 키(`sb_secret_...`)는 절대 넣지 마세요.** config.js는 GitHub에 공개됩니다.
> 공개 키(anon/publishable)는 공개되어도 괜찮습니다. 모든 테이블이 RLS로 "본인 장부만" 보이게 막혀 있기 때문입니다.
> 연결 확인 페이지는 secret 키가 들어 있으면 경고를 띄웁니다.

✅ 확인: config.js에 `YOUR-` 글자가 남아 있지 않습니다.

## 6. GitHub에 올리고 GitHub Pages 켜기

### 6-1. 커밋·푸시
처음 한 번은 git에 이름과 이메일을 등록해야 합니다.
```bash
git config --global user.name "kmlim-kt"
```
```bash
git config --global user.email "GitHub에 등록한 이메일"
```
그다음 저장소 폴더에서 아래 명령을 실행합니다. (원하시면 제가 대신 해 드립니다)
```bash
git add -A
```
```bash
git commit -m "0단계: 스키마, 설정, 연결 확인 페이지"
```
```bash
git push -u origin main
```

### 6-2. GitHub Pages 켜기
1. <https://github.com/kmlim-kt/de_housekeeping> → **Settings** → 왼쪽 **Pages**로 갑니다.
2. **Source**: `Deploy from a branch`, **Branch**: `main` / `/ (root)`을 고르고 **Save**를 누릅니다.
3. 1~2분 뒤 같은 화면 위쪽에 주소가 나타납니다: `https://kmlim-kt.github.io/de_housekeeping/`

### 6-3. 연결 확인
위 주소를 PC와 휴대폰에서 각각 엽니다. 아래 세 항목이 모두 **✔**이면 0단계가 끝난 것입니다.
- 페이지 배포
- config.js 설정
- Supabase 연결 · schema.sql (스키마 버전 1)

| 화면 메시지 | 원인과 해결 |
|---|---|
| 아직 예시 값 그대로입니다 | config.js를 고친 뒤 커밋·푸시했는지 확인하세요. Pages 반영까지 1~2분 걸립니다 |
| schema.sql이 아직 실행되지 않은 것 같습니다 | 2장을 다시 확인하세요 |
| Invalid API key | 키를 잘못 복사했습니다. 앞뒤 공백까지 확인하세요 |
| 서버에 연결하지 못했습니다 | Project URL 오타, 또는 프로젝트가 일시 정지된 상태입니다(1장 참고) |
| 404 페이지 | Pages 설정의 Branch가 `main` / `(root)`인지 확인하세요 |

## 7. 0단계 테스트 시나리오

`tests.sql`이 아래 내용을 자동으로 확인합니다. 하나라도 틀리면 그 항목 이름과 함께 실패합니다.

### 복식부기 로직
| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | **개시 잔액**: 현금 10만, 통장 200만, 카드 미결제 30만 | 기초 순자산 180만, 순자산 180만 |
| 2 | **카드로 식비 3만 원** (차변 식비 / 대변 카드) | 순자산 177만(**3만 원 감소**), 당기 손익 −3만 |
| 3 | **카드대금 33만 원 결제** (차변 카드 / 대변 통장) | 순자산 **그대로 177만**, 카드 잔액 0, 통장 167만 |
| 4 | 시산표 | **차변 합계 = 대변 합계**, 불균형 전표 0건, 회계 등식 성립 |
| 5 | 1월 10일 기준 재무상태표 | 카드대금 결제 전이므로 카드 33만 |
| 6 | 카드 계정 원장 | 누적 잔액 30만 → 33만 → 0 |
| 7 | 급여 분개 3줄 (통장 300만 + 세금 30만 / 급여 330만) | 저장 성공 |
| 8 | 대출 상환 (원금 50만 + 이자 5만 / 통장 55만) | 순자산 472만 (원금 상환은 순자산을 바꾸지 않고, 이자만 줄임) |

### 거부되어야 하는 입력
- 차변 3만 ≠ 대변 2.9만 / 소수 금액(1000.5원) / 한 줄에 차변·대변 동시 / 1줄짜리 전표
- 하위 계정이 있는 상위 계정(예: 보통예금)에 직접 기록 / 3단계 계정 / 시스템 계정·거래 있는 계정 삭제
- 같은 반복 거래 회차를 두 번 등록 / 다른 기기에서 먼저 고친 전표를 옛 버전으로 수정
- RPC를 거치지 않고 관리자 권한으로 넣은 불균형 라인 → 커밋 시점에 DB가 최종 거부

### 수정·삭제·이력
- 수정하면 잔액에 반영됩니다. 휴지통으로 옮기면 잔액에서 빠지고, 복원하면 다시 포함됩니다.
- 영구 삭제는 휴지통에 있는 전표만 가능합니다.
- 생성·수정·삭제·복원·영구삭제가 이력 6건으로 남습니다.
- 같은 전표를 두 번 전송(오프라인 재전송)해도 1건만 저장됩니다.

### 반복 거래
- 매월 31일 반복은 1/31 다음이 **2/28**, 그다음은 **3/31**입니다(말일 보정).

## 8. RLS(보안) 확인 방법 — 다른 계정으로 접근 시도

### 방법 1: tests.sql (자동, 지금 바로)
3장의 tests.sql이 가짜 사용자 A·B를 만들어 다음을 확인합니다.
- B가 A의 계정과목·전표·분개·이력·예산·잔액·월별 손익을 조회 → **0건**
- B가 A의 계정 이름 변경·장부 삭제·전표 저장·전표 삭제·초대 코드 생성 시도 → **모두 실패**
- B가 자기 장부에 A의 계정을 섞어 분개 → **실패**
- A도 전표 테이블에 직접 INSERT/UPDATE할 수 없음 → RPC로만 저장(차대 검증 우회 불가)
- A가 B를 초대하면 → B가 A의 장부를 볼 수 있음. B가 나가면 → 다시 볼 수 없음
- 로그인하지 않은 상태(anon) → 테이블 접근·전표 저장 **모두 실패**

### 방법 2: 실제 두 계정으로 (1단계 완료 후)
1. 이메일 두 개로 각각 가입합니다. 예를 들어 Gmail의 `내주소+a@gmail.com`, `내주소+b@gmail.com`을 쓰면 둘 다 같은 메일함으로 받습니다.
2. A로 로그인해 전표를 몇 건 입력합니다.
3. 다른 브라우저(또는 시크릿 창)에서 B로 로그인한 뒤, 개발자 도구(F12) 콘솔에서 A의 데이터를 직접 조회해 봅니다. 콘솔에 입력할 코드는 1단계 때 드리겠습니다.
   → 빈 결과 `[]`가 나오면 정상입니다.

## 9. (선택, 나중에) 구글 로그인 켜기

구글 로그인은 나중에 켜기로 했습니다. 켤 때 할 일만 미리 적어 둡니다.
1. Google Cloud Console에서 프로젝트를 만들고 **OAuth 동의 화면**을 설정합니다(외부 사용자).
2. **사용자 인증 정보 → OAuth 클라이언트 ID**(웹 애플리케이션)를 만듭니다.
   - 승인된 리디렉션 URI: `https://<프로젝트ID>.supabase.co/auth/v1/callback`
3. Supabase **Authentication → Providers → Google**에 Client ID와 Client Secret을 넣고 켭니다.
4. 앱 쪽 버튼은 제가 추가하겠습니다.
